# Snowball.ai

Программа для Windows на Electron: система хранения промтов. У каждого промта есть название, тип, текст и прикреплённые файлы.
Интерфейс на русском. Владелец не программист, поэтому объясняй простыми словами и без жаргона.

## Где что лежит
- `main.js` — главный процесс: окно (на Windows своя полоска заголовка через `titleBarOverlay`), обработчики IPC, диалоги, настройки, переезд со старых названий программы (`LEGACY_TITLES`).
- `storage.js` — работа с данными: `prompts.json`, `prompts.backup.json`, папка `Файлы/<id промта>/`. Модуль не зависит от Electron, поэтому его можно проверять обычным `node`.
- `preload.js` — мост `window.vsApi` между окном и `main.js`.
- `src/` — интерфейс: `index.html`, `styles.css` (все цвета заданы CSS-переменными, есть светлая и тёмная тема), `app.js` и локальные шрифты.

## Интерфейс
- Слева боковая панель. Сверху разделы: «Промты», «Ассистент» (см. ниже), а также заглушки с пометкой «скоро» — «Скиллы» и «Календарь». Новый раздел — это кнопка `.nav-item` с `data-page`, своя `<section class="view">` в `index.html` и строчка в `els.views` в `app.js`. Внизу «Статистика» и кнопка профиля.
- Меню профиля (кнопка внизу слева) — единственное меню программы: профиль, настройки, тема, обновления, папка с промтами, сохранение в файл и загрузка из файла. Кнопки «⋯» больше нет.
- Страница «Настройки» (открывается из меню профиля): API-ключ и модель ассистента Claude. Позже там будут настройки календаря и других разделов.
- При первом запуске показывается окно приветствия с ником и аватаркой. Его можно пропустить.
- У каждого промта под названием стоит дата: «Изменён …», если промт правили, иначе «Создан …».
- У промта может быть комментарий (поле `comment`): заметки, что учесть при генерации. Он пишется в редакторе (поле «Комментарий», кнопка «Комментарий» у строки сразу открывает редактор на нём), показывается под текстом промта и ищется поиском. «Копировать» копирует только текст промта, без комментария. Правка комментария считается правкой в статистике.

## Ассистент
- Раздел «Ассистент» — чат: слева «История» разговоров, справа лента сообщений, поле ввода (Enter — отправить, Shift+Enter — новая строка, Esc — остановить ответ), кнопка «Новый разговор». В узком окне история прячется за кнопкой «История».
- История: открытый разговор живёт в окне (`chat` в `app.js`) и после каждого законченного сообщения целиком сохраняется в `chats.json` в папке с данными (`chat-save`; ещё `chat-list`, `chat-get`, `chat-delete`; в `storage.js` — `saveChat`, `chatList`, `getChat`, `deleteChat`). Название — начало первого сообщения. Пустой новый разговор не сохраняется. Удаление — по крестику с подтверждением «Удалить разговор?».
- Поле ввода устроено как в Claude: текст сверху, снизу кнопка «Модель» (`#model-btn`, подпись вида «Opus 5.5 · Средне») и кнопка отправки. В меню кнопки — модель (`MODELS`) и «Размышления» (`EFFORTS`: Быстро `low`, Средне `medium`, Глубоко `high`, Очень глубоко `xhigh`, Максимум `max`; это `output_config.effort`). Меню не закрывается после выбора, чтобы можно было выбрать и модель, и размышления. Без ключа в меню подсказка, что отвечает заглушка.
- Кто отвечает: если в «Настройках» сохранён API-ключ — настоящий Claude (`claudeSource` в `main.js`), иначе заглушка (`stubSource`): заготовленные ответы по словам «добавь промт», «улучши», «календарь», «промт», остальное — общий ответ. Пока ключа нет, над чатом пометка «Тестовый режим: отвечает заглушка, а не Claude» со ссылкой «Подключить Claude»; с ключом вместо неё строчка «Отвечает Claude …».
- Путь ответа: окно отправляет весь разговор (`assistant-send`, массив `{ role, content }`), `main.js` присылает событие `assistant` с кусочками: `delta` (текст), `action` (карточка действия), `done` или `error`. Источник ответа — async-генератор `{ type: 'text' }` / `{ type: 'action' }`; оба источника устроены одинаково, окно не знает, кто отвечает.
- Claude: официальный SDK `@anthropic-ai/sdk` (версия 1.x, ключ уходит в заголовке `authorization: Bearer`), поток через `client.beta.messages.stream`. Системная инструкция `SYSTEM_PROMPT` — помощник по промтам для картинок и видео. Модели в `MODELS`: `claude-opus-5-5` (основная, по умолчанию; при отказе API сам повторяет запрос на подходящей модели: `fallbacks: 'default'` с beta `server-side-fallback-2026-07-01`) и `claude-haiku-5-5` (дешёвая, без запасной модели). Размышления по умолчанию `medium`. Выбор хранится в `settings.json` как `assistantModel` и `assistantEffort` (`assistant-set-options`). Инструментов (tools) пока нет.
- Ключ: каждый пользователь вводит свой (репозиторий открытый, в коде и в git ключа быть не должно). Хранится зашифрованным через `safeStorage` в `%APPDATA%\Snowball.ai\claude-key.bin`, не в папке с промтами. Расшифрованный ключ живёт только в `main.js`, в окно он не возвращается: окно знает лишь `hasKey`. «Проверить ключ» (`assistant-check-key`) отправляет один крошечный запрос к `claude-haiku-5-5` и сохраняет новый ключ, только если он работает (или верный, но на счёте нет денег). Ещё есть `assistant-delete-key`.
- Ошибки Claude переводятся на русский в `claudeError`: неверный ключ (401), нет доступа (403), нет денег (402 `billing_error` или 400 «credit balance»), лимит запросов (429), нет интернета, перегрузка (5xx), отказ (`stop_reason: "refusal"`) и слишком длинный ответ (`max_tokens`). При 429, 5xx и обрыве связи SDK сам повторяет запрос 2 раза.
- Проверять без денег: запустить программу с переменной `ANTHROPIC_BASE_URL=http://127.0.0.1:<порт>` и поддельным сервером, который отвечает как API (SDK сам берёт адрес из этой переменной).
- Действия ассистента — только с подтверждением. Карточка «Создать промт „…“?» хранится в `main.js` (`pending`); на «Создать» окно вызывает `assistant-decide`, и промт сохраняется через `store.savePrompt` (считается в статистике), на «Отмена» ничего не происходит. «Новый разговор» и открытие другого разговора вызывают `assistant-reset`: ответ останавливается, а неотвеченные карточки помечаются «Карточка устарела» (`status: 'stale'`), потому что `main.js` их забыл. Так же они выглядят после перезапуска программы.
- Ответы показываются с простой разметкой: абзацы, списки, **жирный**, `код`, блоки ``` с кнопкой «Копировать» (копирование из чата в статистике не считается).
- Дальше: поиск и создание промтов и календарь через tool use (всегда с подтверждением, как карточки заглушки), «Скиллы» — наборы инструкций для ассистента.

## Данные пользователя
- По умолчанию данные лежат в «Документы\Snowball.ai». Папку можно сменить в меню профиля. Настройки хранятся в `%APPDATA%\Snowball.ai\settings.json`: окно, масштаб, папка, тема (`theme`: `system`, `light` или `dark`) и модель ассистента (`assistantModel`). Рядом лежит `claude-key.bin` — зашифрованный API-ключ, если пользователь его ввёл.
- В папке с данными, рядом с `prompts.json`, лежат `profile.json` (ник), `avatar.png` (аватарка 256×256, обрезанная до квадрата), `activity.json` (действия по дням для статистики) и `chats.json` (разговоры с ассистентом). При смене папки они копируются вместе с промтами.
- Статистика: одно действие — это новый промт, правка с настоящими изменениями, каждый прикреплённый файл или копирование промта кнопкой «Копировать». Удаление и загрузка из файла не считаются. При первом запуске версии со статистикой прошлое восстанавливается по датам создания и правки промтов и по датам файлов.
- Не удаляй данные пользователя. Не меняй формат `prompts.json` так, чтобы старые файлы перестали читаться.

## Дизайн
- Тёплая пастельная палитра. Цвета типов: «Статика» — зелёный, «Видео» — синий, «Системные» — красный. Список типов задан в `CATEGORIES` в `app.js`, их цвета — в `styles.css`.
- Шрифты: Unbounded для заголовка, Golos Text для текста, IBM Plex Mono для промтов.

## Сборка
- `npm install`
- `npx electron-builder --win nsis --x64 --publish never` → готовый установщик `dist\Snowball-Setup-<версия>.exe`, рядом `.blockmap` и `latest.yml`
- Перед каждым выпуском увеличивай `version` в `package.json`.
- Не меняй `build.nsis.guid`: по нему новая версия при установке заменяет старую.

## Выпуск и автообновления
- Код лежит на GitHub: `zaklex0/snowball-ai` (открытый репозиторий). `gh` установлен в `C:\Program Files\GitHub CLI\gh.exe`.
- Выпуск: коммит и push, затем `gh release create v<версия>` с тремя файлами из `dist`: `Snowball-Setup-<версия>.exe`, `Snowball-Setup-<версия>.exe.blockmap`, `latest.yml`. Без `latest.yml` установленные программы не увидят обновление.
- Установленная программа (`electron-updater`, блок «updates» в `main.js`) проверяет релизы через 10 секунд после запуска и раз в 4 часа. Сама она ничего не скачивает (`autoDownload = false`). Найдя новую версию, программа показывает баннер «Скачать» / «Не сейчас»: после «Не сейчас» фоновая проверка про эту версию больше не спрашивает, а «Проверить обновления» в меню спрашивает всегда. После «Скачать» в баннере виден процент загрузки, затем появляется кнопка «Перезапустить и обновить». Если пользователь не перезапустит программу, обновление установится, когда он её закроет. При запуске из исходников проверка выключена.
- Версии 1.4.0–1.5.0 ещё скачивают обновления сами, не спрашивая.
- У программы нет цифровой подписи, поэтому `publisherName` не задавай: иначе обновления перестанут устанавливаться.

## Планы
- Инструменты для ассистента Claude (искать и сохранять промты) и календарь (задачи на день, встречи, звонки).
- Примеры промтов для новых пользователей во всех типах: их кладут в `SEED` в `main.js`.
- Версия для телефона или браузера. Промты можно перенести через «Сохранить промты в файл».
